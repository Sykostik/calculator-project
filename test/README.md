# Модульні тести калькулятора

Тести запускаються **на комп’ютері**, а не на ESP32. Справжній код проєкту
(`math_parser.c`, `calc_ui.c`, `ai_overlay.c`, `chat_history.c`, `keypad.c`)
компілюється звичайним `gcc` разом із заглушками, які замінюють дисплей,
GPIO, Wi-Fi, камеру та Gemini.

Папка `test/` не входить у прошивку: у `CMakeLists.txt` файли перелічені явно,
і тестових там немає.

## Що перевіряється (126 тестів)

| Розділ | Що саме |
|---|---|
| Арифметика | порядок дій, дужки, унарний мінус, `%`, `^`, модуль |
| Функції | `sqrt`, `cbrt`, `log`, `log2(8)`, `ln`, `exp`, `fact`, `pi`, `e` |
| Тригонометрія | DEG і RAD, обернені функції, `tan(90)` не визначений |
| Помилки | ділення на 0, корінь з від’ємного, `fact(171)`, `log(0)` тощо |
| Змінна x | обчислення для графіків, чисельна похідна `d/dx` |
| Екран | що показує `=SOLV`: `sin(60)` → `sqrt(3)/2`, `RAD: PI/3` |
| Символьна похідна | підтримувані правила і те, що непідтримуване дає помилку, а не неправильну відповідь |
| Клавіатура | сканування матриці 4×4 на імітованих GPIO, утримання клавіші |
| Введення | шари A–D, курсор, видалення, T9 з таймаутом 800 мс, `Ans`, буфер обміну |
| Історія чату | 8 реплік, видалення найстарішої пари, обрізання довгих відповідей |
| Вікно відповіді ШІ | сторінки по 10 рядків, виділення, копіювання у вираз |

Залізо (дисплей, камера, Wi-Fi, запити до Gemini) перевіряється вручну на пристрої.

## Як запустити

Потрібен `gcc` для комп’ютера (не той, що в ESP-IDF).

**Linux / macOS / WSL:**
```
make -C test
```

**Windows:** встановити MSYS2 (пакет `mingw-w64-ucrt-x86_64-gcc`) і додати `gcc` у PATH, потім:
```
test\run_tests.bat
```

Результат: список `[PASS]` / `[FAIL]` і підсумок. Код виходу 0, якщо всі тести пройшли.

## Відомі помилки

`make -C test known` (або `run_tests.bat known`) додатково запускає 10 тестів
на помилки, знайдені під час перевірки коду (`-2^2`, `2^3^2`, `e-1`, похідна `x^2*3` тощо).
Зараз вони не проходять — це очікувано. Після виправлень вони мають стати зеленими.
